# 設定を畳んで、コミットしてプッシュする

**本文は固まっている前提。** 本文に手を入れるのは [episode-write](../episode-write/SKILL.md)。

## 畳むもの

上から順に。**どれも CRLF。** 新しいファイルは LF で書いてから `perl -pe 's/\r?\n/\r\n/'` で変換し、既にあるファイルは python（`newline=''`）で置換する。**置換は一箇所ずつ、当たった数を assert で確かめる。** `sed -i` は使わない。

1. **年表**（[基礎設定.md](../../../B_設定/基礎設定.md)「年表」）——**本筋回だけ**。直前の本筋回の行の下に、日付と出来事を一行。末尾は「**本文に日付は出さない。** 第N話（本筋N）」の形。
2. **話別設定** `B_設定/話別設定/0NN_題_設定.md`——直前の話の設定ファイルの節立てに合わせる。冒頭の確定事項（種別・由来・題の決め方・帳面の増減・時期）、伝えること、草案から直したところ（**著者の指摘はそう書く**）、舞台、依頼人と人物（新しい苗字）、調べと始末、締め（型と、前の二話の型）、人の出し方、この回で足した設定、触れていないこと。
3. **怪異のファイル** `B_設定/怪異/0NN_名.md`——相手として当たったものは、怪異でなかったものも置く（`006_警固の空き家.md` の形）。
4. **帳面・札・記憶と怪異の法則**——帳面の中身が動いたとき、新しい規則を決めたときだけ。帳面.md「現在の記載」（帳面の中身の正はここだけ。PROJECT_RULES「現在地」は帳面.md を指すだけ）。
5. **進行記録と掲載表**——**[掲載表.md](../../../C_執筆管理/掲載表.md)に一行足す**（掲載・話・種別・題・案）。進行記録は、その話に掛かる節の表（例：安藤の時計の表）を「済」にし、**「## 現在地」の季節と日付の早見の表に、その話の行を足す**（話・時期・覚え書き）。冒頭の一文の話数と本数も直す。**話ごとの要約は進行記録に書かない**——正は話別設定（2026年10月12日に冒頭の表と「各話の到達点」を外した）。
6. **話アイデア**——`git mv` で `執筆済み/I0NN_話数_題.md` へ移す。冒頭に「**済（第N話「題」）**」と、書く段で組み直した点を一段。[README.md](../../../C_執筆管理/話アイデア/README.md)の一覧の行を執筆済みへのリンクに替え、済の印を添える。**旧パスを参照しているリンクを grep で拾って張り替える**（進行記録・アイデア.md・ほかの話アイデア）。
   ```bash
   grep -rn "I0NN_" --include=*.md . | grep -v "^./D_"
   ```
7. **PROJECT_RULES**——「執筆の作法」の**締めの型の一覧に、その話を足す。** 「現在地」は冒頭の一文の話数と本数だけ直す（季節は進行記録、帳面は帳面.md、各話の要約は話別設定が持つ）。
8. **連載の組み方**——依頼人の持ち札の「既出」に、その話の依頼人を足す。

## 確かめる

```bash
cd "$(git rev-parse --show-toplevel)"
git status --short
for f in $(git diff --name-only) $(git ls-files --others --exclude-standard); do file "$f" | grep -v CRLF; done
git diff --stat
```

CRLF でないファイルが出たら直す。

## コミットしてプッシュする

- **main に直接コミットする。** ブランチは切らない。
- **ファイルを名指しで add する。** `git add -A` は使わない（別の作業の書きかけが混ざる）。`git mv` 済みの旧パスは add に含めない（含めると pathspec で全体が止まる）。
- メッセージは一行目に「第N話「題」と設定一式。〜」、本文に要点、末尾に会話の指示にある Co-Authored-By の行。

```bash
git add A_本編/0NN_第N話_題.md B_設定/話別設定/0NN_題_設定.md （以下、名指し）
git commit -F - <<'MSG'
（メッセージ）
MSG
git push
git log --oneline -1
```

## 書き出し（標準）

**プッシュのあと、毎回やる。** 頼まれるのを待たない（2026年10月8日、著者の指定。設定を畳む→コミットプッシュ→単話の書き出し、までが一続きの標準手順）。

単話で、なろう・カクヨムの両方に出す。手順と検査は [export-honbun-txt](../export-honbun-txt/SKILL.md) の「単話」「確認」「報告」のとおり。**変換記録の表を報告に出す。** 書き出しは生成物なのでコミットしない。

## 投稿先には触らない

なろう・カクヨムの確認や更新は、明示的に頼まれたときだけ。書き出したあとでも、こちらから持ちかけない。
